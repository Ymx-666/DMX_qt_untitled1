## 2. 对参考专利写法的归纳

### 2.1 值得采用的写法

高相关专利通常采用“独立权利要求给出闭环技术链、从属权利要求逐层展开、说明书用同一层级复述并补公式与参数”的结构。例如：

1. 独立权利要求先明确输入数据、处理步骤、步骤之间的依赖关系和输出结果，而不是只写算法名称。
2. 从属权利要求再限定数据字段、时间窗、坐标转换、门限、代价函数、状态更新及设备/介质形式。
3. 背景技术只指出与本发明要解决的问题直接相关的缺陷，不写成行业综述。
4. “有益效果”与区别特征逐项对应，避免只写“提高准确率、提高效率”而没有机制。
5. 具体实施方式同时给出一般表达和一组可复现参数，使保护范围不被单一数值锁死，又能满足充分公开。

### 2.2 本方案不应照搬的常见上位表述

以下内容已经存在密集公开，不能单独作为专利二的核心：

- 周扫相机生成 360°全景并在全景上标记目标；
- 对可见光、红外或其他传感器结果进行一般的时空融合；
- 使用卡尔曼滤波、最近邻或匈牙利算法进行多目标跟踪；
- 在全景左右边界复制区域并替换目标 ID；
- 给融合目标分配稳定批号，来源变化时保持批号；
- 将方位和物理距离换算成雷达 PPI 极坐标；
- 预计算极坐标扫描线查找表并直接写显存；
- 根据相机视场角和图像纵坐标计算目标俯仰角或相对高度角；
- 将方位角映射为环形角度、将俯仰角映射为环形半径；
- 单纯将彩色图和黑白图进行像素级融合。

因此，本专利二不应命名为宽泛的“一种多传感器目标融合方法”或“一种极坐标显示方法”。

## 3. 推荐名称与摘要草案

### 3.1 推荐名称

首选名称：

> 一种用于周期周扫双成像通道的目标事件融合与极坐标态势显示方法、系统、设备及存储介质

备选名称：

> 一种基于扫描相位约束的双通道目标事件归并及全景极坐标显示方法

首选名称覆盖较完整；备选名称更突出创造性中心，但“全景极坐标”容易被误解为普通坐标投影。

### 3.2 摘要草案

本发明公开一种用于周期周扫双成像通道的目标事件融合与极坐标态势显示方法。接收彩色通道和单色通道异步输出的目标检测记录，将各记录映射到统一的环形全景坐标，并根据经校正的全景纵坐标和设备垂直视场角确定目标相对高度角；先依据来源帧标识实施同源帧互斥，再依据同序号近时配对、通道相位延迟配对及跨扫描周期重访三类时间关系建立候选事件，并结合环形方位差、高度角差、扫描周期残差、目标框形态、局部外观及类别兼容性确定关联代价。关联成功时沿用稳定事件标识并更新来源、命中次数、类别、置信度和生命周期，否则建立新事件。显示时保持原始关联方位不变，仅以独立北向偏置同步变换全景背景和事件显示方位，并以与背景一致的高度角—半径变换叠加融合事件。该方法适用于无物理距离量测的周扫光电全景数据，可减少双通道重复事件及同帧多目标误合并，并避免图像分辨率变化或显示校准改变历史关联结果。

## 4. 专利边界与创造性中心

### 4.1 与发明专利一的边界

发明专利一负责：原始图像输入、目标检测、天空区域处理、固定杂波判定及抑制。

发明专利二从“检测器已经输出一条目标检测记录”开始，负责：

- 把异步的 RGB/BW 检测记录归并成事件；
- 保持事件 ID、来源和生命周期；
- 在环形全景坐标中处理 0°/360°边界；
- 将融合事件与全景背景一致地映射到高度极坐标态势图。

固定杆体识别、静态背景建模、硬负样本、天空 mask 和检测网络结构均不写入专利二的独立权利要求。

### 4.2 建议保护的必要组合

本方案的创造性中心不是某一个门限，而是以下特征之间的协同：

1. 双通道目标记录统一到**环形全景坐标**，保留通道、源帧和接收时间。
2. 根据周扫周期及通道相位关系，区分**同序号近时配对、相位延迟配对、跨圈重访**，而不是只使用一个普通时间窗。
3. 在计算相似度之前执行**同一来源帧互斥**，防止一帧内同时出现的多个目标被合并。
4. 将经校正的全景纵坐标按设备垂直视场角换算为相对高度角，用环形方位差、高度角差、周期残差、形态、外观和类别兼容性共同建立事件关联约束；纵向像素差仅作为未完成标定时的兼容量。
5. 关联后保留稳定事件 ID，并更新来源集合、命中次数、类别证据、代表 ROI 和生命周期。
6. 把用于关联的原始方位与用于界面校准的显示方位分层保存；北向偏置只作用于背景投影和事件显示，不回写关联数据。
7. 采用同一标定参数把全景背景和融合事件从纵向图像坐标变换为高度角再映射至极坐标半径；所述半径表达**视线高度角**而不是未经测量的目标距离或物理高度。

目前检出的单篇文献尚未完整公开以上组合。审查阶段更可能采用多篇文献组合评价创造性，因此说明书必须把“周期相位约束、同帧互斥、稳定事件及显示解耦”产生的联合技术效果写清楚。

## 6. 术语与数据对象

### 6.1 周扫周期与通道

- 第一成像通道：本项目 RGB 彩色图像通道；当前已确认装机型号为海康机器人`MV-CL044-91NC`、序列号`DA8887960`，型号规格为4096×3线彩色CMOS、7 μm像元和2.5GigE接口。
- 第二成像通道：本项目 BW 单色图像通道；当前已确认装机型号为海康机器人`MV-CL044-91NM`、序列号`DA8775974`，型号规格为4096×4线黑白CMOS、7 μm像元、2.5GigE接口并支持1-Line/2-TDI/4-TDI。没有证据证明 BW 必然是红外，因此申请文件不要直接写“红外”。
- 周扫周期 `T`：设备完成一次 360°扫描的时间。当前回放实施例为 8000 ms。
- 分段数 `N`：每圈送入处理链的图像分段数。当前实施例为 16。
- 线阵空间轴：线阵传感器单次曝光得到的一行空间采样，对应海康参数 `Width`；本设备安装后该轴承担垂直方向成像。
- 扫描合成轴：相机随转台运动连续采集的行序号，对应海康参数 `Height` 所累计的行数；该轴表达扫描时间/方位，不是面阵传感器的另一条光学空间轴。
- 通道相位延迟 `τc`：同一空间方向在两通道数据链中形成对应记录时的标定延迟。当前存在同序号近时配对及约半圈延迟配对两种工程路径。
- 垂直视场角 `FOV_v`：沿线阵传感器空间轴覆盖的总角度，设备当前确认值为 `26.88°`。该空间轴经逆时针旋转90°和水平镜像后映射为全景纵坐标；递交前仍需核对有效 `Width/Offset X`、安装上下方向及是否裁剪。
- 相对高度角 `β_rel`：目标视线相对于光轴的上下角度，向图像顶部/高空方向为正；仅有视场角和像素位置时能够计算该量。
- 绝对高度角 `β_abs`：相对于当地水平面或约定基准面的目标视线角，需在 `β_rel` 上叠加光轴俯仰/设备姿态标定；未取得该标定前不得把 `β_rel` 直接称为绝对高度角。

### 6.2 目标检测记录

一条检测记录 `D_i` 至少包括：

```text
D_i = {
  channel, sourceFrameKey, sequence, timestamp,
  panoX, panoY, rawAzimuth,
  relativeElevation, absoluteElevation, calibrationVersion,
  class, classConfidence, detectionConfidence,
  box, boxArea, boxAspect,
  roiPath, appearanceHash
}
```

当前 `TargetRecord` 还保存 `id`、`firstTime`、`lastTime`、`lastStream`、`state`、`hits`、`score`、`trackAgeSec` 等字段。实现位置为 `radar_ui/targetrecord.h`。

### 6.3 融合事件

融合事件 `E_j` 不是带物理速度和距离预测的雷达航迹，而是将多条检测记录判定为同一观察对象后形成的持续事件。事件至少保存：

- 稳定事件 ID；
- 首次和末次观察时间；
- 最近来源帧和来源通道；
- 已出现通道集合，如 RGB、BW 或 RGB+BW；
- 当前代表类别及类别置信度；
- 原始方位、全景纵坐标、相对高度角、可选绝对高度角、标定版本和代表 ROI；
- 命中次数、融合置信度、事件状态和年龄。

该定义可以避免把当前功能错误描述为具备速度估计、距离估计和轨迹外推的完整目标跟踪系统。

## 7. 系统结构

系统由以下模块组成：

1. **检测记录接收模块**：异步接收 RGB/BW 检测结果。本模块不限定检测器内部算法。
2. **统一坐标与高度角模块**：把分段图坐标映射到 `65536×4096` 环形全景坐标，计算原始方位，并根据纵向有效视场角和标定参数计算相对高度角或绝对高度角。
3. **扫描相位模块**：取得周扫周期、分段序号、通道配对关系和通道相位延迟。
4. **互斥与候选生成模块**：先执行同源帧互斥，再按时间关系建立候选事件。
5. **联合关联模块**：执行环形方位角、高度角、周期残差、形态、外观和类别门控，并计算代价；未标定时兼容使用纵向像素位置。
6. **事件更新模块**：新建事件或沿用稳定 ID，更新来源、类别、置信度、ROI、状态及日志。
7. **显示坐标模块**：保存原始方位和显示北向偏置之间的可逆关系。
8. **高度极坐标投影模块**：将全景背景与事件分别投影到同一极坐标画布，事件层独立绘制。

数据流为：

```text
RGB/BW检测记录
    -> 统一环形全景坐标及高度角归一化
    -> 源帧互斥
    -> 周扫相位候选窗口
    -> 多证据门控与最小代价选择
    -> 融合事件/稳定ID/生命周期
    -> 原始方位与显示方位解耦
    -> 高度极坐标背景和事件图层
```

## 8. 方法详细步骤

### S1：接收异步检测记录

接收两个成像通道分别输出的检测记录。记录到达顺序可以不同，但每条记录必须带有源帧标识和采集或接收时间戳。

本项目当前从候选 ROI 文件名提取 `sourceFrameKey`；文件名尾部序号用于得到 `sequence`。专利文本应写成“源帧标识”，文件名解析只作为一种实施例。

### S2：映射统一环形全景坐标

对于第 `k` 个分段图中的检测中心 `(x_i,y_i)`，一种实施方式为：

```text
u_i = mod(k * W_s + x_i * W_s / W_f, W_p)
v_i = clamp(y_i * H_p / H_f, 0, H_p - 1)
θ_i = mod(360° * u_i / W_p + δ_device, 360°)
```

其中：

- `W_s` 为分段在全景中的宽度；
- `(W_f,H_f)` 为源图尺寸；
- `(W_p,H_p)` 为全景尺寸；
- `δ_device` 为设备坐标标定量，不是界面北向偏置。

当前直接 YOLO worker 已按 `tileIndex * sliceWidth + cx` 映射 `panoX`，并对 `panoX` 执行全景宽度取模。

本设备采用线阵相机。根据海康手册，线阵输出帧的 `Width` 是由Sensor决定的横向空间分辨率，`Height` 是一帧累计的扫描行数。一帧4096×4096图像不能按4096×4096面阵传感器理解。设旋转前线阵空间坐标为 `x_l∈[0,W_l-1]`、累计行坐标为 `y_l∈[0,H_l-1]`，按当前“逆时针旋转90°后水平镜像”的处理，在不缩放时有：

```text
x_processed = H_l - 1 - y_l
y_processed = W_l - 1 - x_l
```

因此，处理后的 `panoY` 来自线阵Sensor的 `Width` 轴并发生方向反转，适合承载26.88°垂直视场；`panoX`来自累计扫描行和转台运动，应由行序号—编码器角度关系确定。当前 `panoX/W_p×360°` 是均匀扫描假设下的实现，真实方位标定还应使用逐行编码器角度或至少使用分段起止角插值。

对纵向坐标，当前工程把检测中心映射到全景 `panoY`；极坐标投影中全景顶部按当前安装约定对应高空外圈。设去畸变并完成双通道纵向配准后的坐标为 `v_u`，全景有效高度 `H_p` 等于变换后的有效线阵 `Width` 采样数，主点纵坐标为 `c_y`，设备有效垂直视场角为 `FOV_v`，则针孔模型可写为：

```text
f_y       = H_p / (2 * tan(FOV_v / 2))
β_rel     = atan2(c_y - v_u, f_y)
β_abs     = β_axis + β_rel
Δβ_box    = β_rel(v_top) - β_rel(v_bottom)
```

其中 `β_axis` 为光轴相对于当地水平面或约定基准面的俯仰角。没有 `β_axis` 时只能报告相对高度角 `β_rel`，不能声称得到绝对高度角；没有目标距离或地面几何约束时，更不能由该式得到目标海拔或物理高度。若全景已经按等角纵向投影校正，也可采用线性模型。当前测试构建把首末像素中心直接映射到 `±FOV_v/2`，其计算式为：

```text
β_rel,linear = (0.5 - v_u/(H_p-1)) * FOV_v
```

若按像素单元边界定义有效视场，也可写为 `(c_y-v_u)FOV_v/H_p`。两种写法的分母分别为 `H_p-1` 和 `H_p`，数值很接近但不能在同一测试表中混用；正式实施例应固定投影定义、像素中心约定和标定版本。

当前设备按用户确认值取 `FOV_v=26.88°`、`H_p=4096`，以 `c_y=(H_p-1)/2=2047.5` 计算，可得：

| 标定量 | 数值 |
| --- | ---: |
| 半视场角 | `13.44°` |
| 按图像高度计算的名义平均角分辨率 | `26.88/4096 = 0.0065625°/px` |
| 当前端点线性模型像素步长 | `26.88/4095 ≈ 0.0065641°/px` |
| 针孔模型等效纵向像素焦距 `f_y` | `8570.06 px` |
| 光轴附近角分辨率 | 约 `0.0066856°/px` |

以下数值便于研发人员核对方向和计算结果，正值表示高于光轴：

| `panoY` | 线性近似 `β_rel` | 针孔模型 `β_rel` |
| ---: | ---: | ---: |
| 0 | `+13.4400°` | `+13.4368°` |
| 512 | `+10.0792°` | `+10.1579°` |
| 1024 | `+6.7184°` | `+6.8104°` |
| 1476 | `+3.7514°` | `+3.8152°` |
| 2047.5 | `0°` | `0°` |
| 2856 | `-5.3071°` | `-5.3893°` |
| 3072 | `-6.7249°` | `-6.8170°` |
| 3584 | `-10.0857°` | `-10.1644°` |
| 4095 | `-13.4400°` | `-13.4368°` |

上述计算以 `26.88°` 确为当前朝向下的纵向有效视场角、主点位于图像中心且畸变已忽略为前提。递交前需要用线阵相机专用的受控移动/转动标定目标、经纬仪或已知仰角地标，实测 `c_y`、一维射线映射/畸变、两通道纵向偏移、光轴俯仰及设备滚转；不能把运动合成帧直接套用面阵相机的静态棋盘格流程。否则表中数值只能作为理想模型实施例。

当前代码状态需要特别说明：配置文件和 `AppConfig` 已保存 `camera.verticalFovDeg=26.88`，直接YOLO及传统检测记录已包含 `panoY`；但 `TargetRecord.elevationAngleDeg` 目前只在 `DMX_TEST_BUILD` 中按上述端点线性模型赋值，正式构建不会生成该角度，且尚未执行内参去畸变、通道偏移和光轴姿态补偿。因此当前可批量回算“理想相对视线角”，不能直接形成“真实绝对高度角”结论。具体操作和计算工具见 `发明专利二附图与对照材料/测角与标定/`。

### S3：确定周扫周期和通道相位

周扫周期 `T` 可以由设备配置直接给出，也可以由连续扫描边界时间戳的中位数或稳健滤波估计：

```text
T_hat = median(t_boundary,m - t_boundary,m-1)
```

BW型号`MV-CL044-91NM`支持1-Line、2-TDI和4-TDI，而RGB型号为1-Line。实施时应把两通道实际成像模式、行频、曝光时间、行触发延迟和编码器换算参数写入相位标定版本；BW成像模式或行频变化后，不应继续沿用旧的固定通道相位偏差，而应重新估计或校验。

当前实施例从回放配置取得 `T=8000 ms`，关联代码也以 8000 ms 计算跨圈残差。

建议补强：将硬编码 8000 ms 改为配置值或在线估计值，并在事件日志中记录本次使用的 `T_hat`。这会使权利要求中的“根据扫描周期”获得更强的工程支持。

### S4：执行同源帧互斥

若检测记录的 `sourceFrameKey` 与候选事件最近一次更新所用的源帧标识相同，则该检测记录不得归并到该候选事件。

该步骤先于类别、位置和外观相似度计算。即使一帧中的两只鸟类别相同、方位很近，也保持为两个事件，避免“越相似越容易误合并”的问题。

当前代码在 `evaluateTargetMatch(...)` 的入口直接拒绝相同 `frameKey`，已实现该行为。

### S5：按扫描相位划分时间关系

对新记录与候选事件计算时间差：

```text
Δt = |t_i - t_j|
```

至少划分以下关系：

1. **跨通道同序号近时配对**：通道不同、源帧序号相同且 `Δt <= G_pair`。
2. **跨通道相位延迟配对**：通道不同且 `Δt` 位于通道相位延迟 `τc` 周围的窗口。
3. **同通道相邻帧关系**：通道相同、序号差在限定范围且 `Δt <= G_adjacent`。
4. **跨圈重访关系**：通道相同或满足规定的来源关系，并且时间差接近扫描周期的整数倍。

跨圈重访残差为：

```text
n = max(1, round(Δt / T))
ε_T = |Δt - nT|
```

只有 `ε_T <= G_revisit` 时才进入跨圈候选集合。

三类核心窗口的区别在于：近时配对利用同序号强证据，相位延迟配对补偿两通道的观测相位，跨圈重访利用整数圈周期残差。不能把它们合并成一个无解释的大时间窗。

### S6：计算环形空间差和图像证据

环形方位差为：

```text
d_θ = min(|θ_i-θ_j|, 360°-|θ_i-θ_j|)
```

因此，位于 `359.8°` 和 `0.2°` 的两个记录方位差为 `0.4°`，无需复制全景边界区域。

其他差异量包括：

```text
d_v = |v_i-v_j|
d_β = |β_i-β_j|
r_A = max(A_i,A_j) / min(A_i,A_j)
r_Q = max(q_i,q_j) / min(q_i,q_j)
d_H = Hamming(hash_i,hash_j)
```

其中 `A` 为目标框面积，`q` 为长宽比，`hash` 为局部外观哈希。完成标定后优先使用 `d_β`，使不同分辨率或不同有效视场的通道先各自换算高度角再关联；当前代码仍使用 `d_v`，因此高度角门控属于建议补强项。

按平均角分辨率 `0.0065625°/px`，当前常用纵向像素门限可近似换算为：`100 px≈0.6563°`、`120 px≈0.7875°`、`180 px≈1.1813°`、`256 px≈1.6800°`、`300 px≈1.9688°`、`320 px≈2.1000°`、`420 px≈2.7563°`；跨圈动态门 `96~416 px` 约对应 `0.63~2.73°`。正式参数应按针孔模型在候选点位置计算，以上仅用于旧像素门限的迁移初值。

当前外观实施方式：以目标框中心截取边长不小于 32 像素、约为目标框最大边 3 倍的区域，缩放为 `9×8` 灰度图，逐行比较相邻像素形成 64 位 dHash，再计算汉明距离。

### S7：按关系类型实施门控和代价选择

先针对不同关系类型使用不同门限，再计算联合代价。一般式可写为：

```text
C = wθ*dθ/Gθ + wβ*dβ/Gβ + wt*rt/Gt
    + wA*|ln(rA)| + wQ*|ln(rQ)|
    + wH*dH/64 + wc*Pclass
```

其中：

- `rt` 对近时配对可取 `Δt`，对相位延迟配对可取 `|Δt-τc|`，对跨圈重访取 `ε_T`；
- `dβ` 为按各通道标定参数得到的高度角差；尚未完成角度标定时可以 `dv/Gv` 代替该项；
- `Pclass` 为类别不兼容惩罚；
- 各门限和权重根据关系类型选择。

当前实现按记录到达顺序遍历事件集合，在通过硬门控的事件中选择代价最小者，不使用匈牙利算法。这样可以与 CN115170620A 等专利的全局匈牙利匹配形成区别。

类别规则为：

- 同通道跨圈类别冲突时拒绝关联；
- 跨通道同序号配对允许分类不一致，但必须满足更严格的方位、纵向位置和形态条件，再由类别置信度较高的记录决定代表类别；
- 跨通道相位延迟配对原则上要求类别一致。

### S8：建立或更新融合事件

若不存在合格候选事件，则分配新事件 ID，设置 `hits=1`、首次/末次时间及初始状态。

若存在合格候选事件，则：

1. 沿用原事件 ID；
2. `hits = hits_old + 1`；
3. 来源更新为 RGB、BW 或 RGB+BW；
4. 融合置信度取衰减后的历史置信度与当前置信度中的较大值；
5. 代表类别取类别置信度更高的一方；
6. 代表 ROI 取图像置信度更高的一方；
7. 更新末次时间、事件年龄和状态；
8. 输出包含模式、时间差、方位差、纵向像素差、高度角差、标定版本、形态比、哈希距离和命中次数的可审计日志。

当前实施例的置信度更新为：

```text
confidence_new = max(0.92 * confidence_old, confidence_in)
score_new      = max(0.92 * score_old, score_in)
```

该数值写入从属权利要求会过度限缩，宜放入实施例。

### S9：确定生命周期和显示优先级

当前生命周期规则为：

| 状态 | 条件 |
| --- | --- |
| `new` | 未满足其他状态条件 |
| `tracking` | `hits >= 2` 或 `confidence >= 0.55` |
| `confirmed` | `hits >= 3` 且 `confidence >= 0.45` |
| `stale` | 距离末次观察时间超过显示保留时长的 `2/3` |

当前显示优先级由状态、置信度、新鲜度、命中次数和检测评分共同计算；列表最多显示 7 个事件，当前选中事件优先保留。配置中的雷达候选容量为 20。

### S10：解耦原始方位与显示北向

事件关联和日志始终使用原始方位 `θ_raw`。用户设置北向偏置 `δ_N` 后，仅计算：

```text
θ_display = mod(θ_raw - δ_N, 360°)
θ_raw     = mod(θ_display + δ_N, 360°)
```

全景背景在进入极坐标投影前同步作水平方向循环移位。北向偏置不写回目标原始方位，不改变历史事件关系，也不在程序重启后持久化。

这一分层是专利二的重要区别特征：普通雷达显控往往直接修正目标显示角，而本项目需要保证用户交互校准不会改变事件融合证据。

### S11：生成高度极坐标背景并叠加事件

对极坐标画布中的像素 `(x,y)`，以画布中心 `(cx,cy)` 计算：

```text
r = sqrt((x-cx)^2 + (cy-y)^2)
θ = atan2(x-cx, cy-y)
u = Wp * mod(θ,2π)/(2π)
v = (Rout-r)/(Rout-Rin) * (Hp-1)
```

其中正北为 `0°`、顺时针为正方向；外圈采样全景图像顶部的高空区域，内圈采样较低高度角区域。

事件点的归一化半径为：

```text
ρ_event = bound(ρmin, 1 - panoY/(Hp-1), ρmax)
```

当前 `ρmin=0.08`、`ρmax=0.96`。事件点使用 `θ_display` 和 `ρ_event` 绘制。

上述公式是当前代码采用的线性纵坐标映射。按 `26.88°` 有效垂直视场角引入高度角后，有两种一致实现：

1. **等角/线性实施方式**：使用 `β_rel=(c_y-v)FOV_v/H_p`，背景与事件仍采用当前线性映射。由于角度与纵坐标线性对应，原有视觉对齐保持不变。
2. **针孔标定实施方式（建议补强）**：背景像素和目标标记都先转换为高度角，再使用同一角度—半径函数：

```text
ρ(β) = ρmin + (β-βmin)/(βmax-βmin) * (ρmax-ρmin)
v(β) = c_y - f_y * tan(β-β_axis)
```

其中 `βmax` 对应高空外圈，`βmin` 对应低高度角内圈。极坐标背景在每一半径位置通过逆式 `v(β)` 取样，事件使用其标定高度角通过同一个 `ρ(β)` 取半径。不得只对事件标记使用针孔高度角，而继续对背景使用未经对应修正的线性纵坐标，否则标记会与背景产生系统性径向错位。

必须在说明书中明确：这里的半径是视线高度角编码，不是目标到设备的物理距离，也不是目标物理高度。否则会造成技术事实错误，也容易落入雷达距离极坐标及全景物高测量现有技术。

事件图层在背景、网格和扫描线之后独立绘制。点大小可随置信度变化，颜色随新鲜度衰减，`stale` 事件使用虚线或降权显示。

对比四组方法：

| 组别 | 方法 |
| --- | --- |
| A | 仅普通欧氏坐标最近邻 |
| B | 环形角距离 + 单一时间窗 |
| C | B + 周期残差/通道相位窗口 |
| D | C + 同源帧互斥 + 外观/形态/类别门控，即本方案 |

- 事件 ID 准确率、ID switch 次数；
- 同帧多目标误合并率；
- 跨通道重复事件率；
- 跨圈漏合并率；
- 0°/360°边界关联准确率；
- 每条记录平均关联耗时和 P95；

## 13. 说明书撰写框架

### 13.1 技术领域

本发明涉及光电全景监视、图像目标事件关联和图像坐标显示技术领域，尤其涉及一种用于周期周扫双成像通道的目标事件融合与极坐标态势显示方法、系统、设备及存储介质。

### 13.2 背景技术建议文字

周期周扫光电设备以离散分段方式重复观察 360°场景。两个成像通道的图像和检测结果可能异步到达，同一目标可能在同序号通道对、存在相位延迟的通道数据以及后续扫描圈中重复出现。若仅按普通时间邻近或直角坐标距离合并，会出现四类问题：一是一帧中距离较近的多个真实目标被错误合并；二是跨通道或跨圈的同一目标重复建立事件；三是不同图像高度、裁剪或有效视场下的纵向像素差不可直接比较；四是全景 0°/360°边界和用户北向显示校准使目标标记与背景错位，甚至改变历史事件的关联结果。

已有技术分别公开了周扫全景目标检测、异步多传感器融合、目标生命周期、全景边界 ID 继承和雷达极坐标显示，但未针对同一周期周扫设备的双成像通道，利用源帧互斥和多类扫描相位关系形成持续事件，并将事件原始关联坐标与可交互显示坐标分层处理。

### 13.3 要解决的技术问题

1. 双通道异步且稀疏重访条件下，怎样判断多条检测记录是否属于同一观察事件；
2. 怎样避免同一帧中多个相似目标被错误归并；
3. 怎样在 0°/360°边界保持一致的方位距离；
4. 怎样利用设备纵向视场角把全景纵坐标归一化为可跨分辨率比较的相对高度角；
5. 怎样在没有物理距离量测时形成与全景背景一致的极坐标态势显示；
6. 怎样保证用户调整正北方向时只改变显示，不破坏事件 ID 和历史关联。

### 13.4 有益效果对应关系

| 区别特征 | 直接技术效果 |
| --- | --- |
| 同源帧互斥 | 降低同帧多目标误合并 |
| 三类扫描相位时间关系 | 降低双通道和跨圈重复建事件 |
| 周期残差而非单纯大时间窗 | 在允许多圈重访的同时排除不符合扫描节拍的记录 |
| 环形方位差 | 统一处理 0°/360°边界，不复制图像区域 |
| 纵向视场角归一化高度角 | 降低图像尺寸或通道有效视场变化对纵向关联门限的影响 |
| 形态、外观和类别分级门控 | 在稀疏采样时抑制空间邻近但外观不兼容的误关联 |
| 稳定事件 ID 与可审计日志 | 支持持续显示、复核和参数回归 |
| 原始方位/显示方位分层 | 调整北向时不改变事件关联与历史数据 |
| 背景和事件共用高度角—半径变换 | 无测距光电数据也能一致形成态势图，并避免目标标记与背景径向错位 |

## 18. 结论

发明专利二最适合保护的不是“检测、融合、显示”三个普通功能的并列，而是一个有因果关系的处理闭环：

> 周期周扫双通道检测记录进入统一环形坐标并按设备视场角归一化为相对高度角后，先以源帧互斥保护同帧多目标，再以通道相位和整数圈周期残差约束稀疏重访关联，形成具有稳定 ID 和生命周期的融合事件；随后保持关联原始方位不变，仅在显示层同步校准全景背景和事件方位，并使背景与事件共用高度角—半径变换生成非距离型极坐标态势图。

这一闭环与当前 DMX 项目代码、日志和界面均有直接对应，也比“普通异步融合”或“普通极坐标显示”更容易说明区别特征及协同技术效果。
