# 识别目标的视线角获取与标定指南

> 对应设备参数：全景尺寸 `65536×4096`，当前已确认纵向有效视场角为 `26.88°`。
> 核心结论：已知相机总视场角后，可以根据检测框位置计算目标相对于相机光轴的**理想相对视线角**；要取得可称为“真实绝对高度角”的结果，还必须完成内参、畸变、安装姿态和零位标定。

## 1. 先区分四个不同的量

| 名称 | 能否仅由FOV和像素得到 | 含义 |
| --- | :---: | --- |
| 相对视线高度角 `βrel` | 可以估算 | 目标中心视线相对于相机光轴的上下角度。 |
| 绝对视线高度角 `βabs` | 不可以 | 目标视线相对于当地水平面或约定基准面的角度，还需要光轴俯仰、滚转和平台姿态。 |
| 目标角尺寸 | 可以估算 | 分别换算目标框上下边缘或左右边缘后得到的角度差，不是目标实际物理尺寸。 |
| 目标物理高度/海拔 | 不可以 | 还需要目标距离、设备位置、地面或地球曲率等几何条件。 |

因此，日常口头所说“目标对应的视场角”应在日志和专利材料中改成更准确的术语：**目标中心视线方位角、目标中心相对高度角、目标垂直/水平角尺寸**。

## 2. 当前项目已经具备的数据

代码核对结果如下：

1. `dmx_config.json` 已设置 `camera.verticalFovDeg=26.88`。
2. RGB通道为海康机器人`MV-CL044-91NC`、序列号`DA8887960`，4096×3线彩色CMOS；BW通道为`MV-CL044-91NM`、序列号`DA8775974`，4096×4线黑白CMOS；两者像元均为7 μm。
3. 原始4096×4096图像进入检测前执行“逆时针旋转90°，再水平镜像”。
4. 直接YOLO和传统检测链均根据检测框中心生成 `panoX`、`panoY`；候选JSON还保存 `panoBoxX1/Y1/X2/Y2`。
5. 当前方位角按 `panoX/65536×360°` 计算。
6. 当前目标高度角仅在 `DMX_TEST_BUILD` 下按线性模型写入 `TargetRecord`；正式构建不会填充该字段。
7. 当前线性计算没有执行镜头去畸变、双通道纵向偏移校正和光轴姿态补偿，所以不能将界面值称为标定真值。

### 2.1 线阵相机必须采用的坐标解释

海康线阵相机手册说明：相机输出的一帧图像由多行图像合成；`Width/Width Max`表示Sensor线方向的空间分辨率，`Height/Height Max`表示一帧累计的扫描行数。由此，本项目的4096×4096输出并不表示相机具有4096×4096的二维面阵传感器。

按当前软件“逆时针旋转90°，再水平镜像”的处理，旋转前的线阵坐标和处理后坐标满足：

```text
xprocessed = Hline - 1 - yline
yprocessed = Wline - 1 - xline
```

所以：

- 最终 `panoY` 对应原始线阵Sensor的 `Width`空间轴，且方向反转；已经确认的26.88°垂直视场角应作用在这条轴上。
- 最终 `panoX` 对应累计扫描行/时间和转台方位，不能套用普通面阵相机“水平像素+水平FOV”的静态公式。
- 当前图像恰好是4096×4096，两个数值相同会掩盖轴的含义；说明书和程序字段必须写明 `Hp=有效线阵Width`，而不是笼统写“相机图像高度”。
- 全景顶部是否代表正高度角，还需用一个已知高于光轴的目标做方向核验，避免相机安装方向或 `Reverse X/Reverse Scan Direction`配置使符号反转。
- RGB型号不支持硬件镜像，而BW型号支持水平镜像，因此必须分别核对两通道坐标方向；不能仅凭RGB图像方向推断BW方向。

## 3. 仅知道26.88°时怎样计算

### 3.1 选取目标代表点

对飞鸟、无人机等空中小目标，使用检测框中心：

```text
u = (x1+x2)/2
v = (y1+y2)/2
```

在本项目中，检测链已经把该点映射为 `panoX、panoY`。如果从候选JSON回算，直接使用 `panoY`，不要再对坐标重复旋转或镜像。

### 3.2 理想针孔模型

设变换后的全景有效高度 `H=4096`；这里的4096来源于有效线阵 `Width`，不是累计扫描行数 `Height`。主点暂取 `cy=(H-1)/2=2047.5`，纵向有效视场角 `FOVv=26.88°`：

```text
fy = H / [2 tan(FOVv/2)] ≈ 8570.060 px
βrel = atan2(cy-vu, fy)
```

其中 `vu` 是去畸变并完成通道纵向校正后的坐标。没有标定时可暂取 `vu=panoY`。图像顶部为正角，底部为负角。

### 3.3 当前软件采用的线性模型

```text
βlinear = [0.5-panoY/(H-1)] × FOVv
```

它适合等角投影或快速试算，但不等于针孔模型。以 `panoY=2856` 为例：

- 当前线性模型：约 `-5.3071°`；
- 理想针孔模型：约 `-5.3893°`；
- 两者相差约 `0.0823°`。

在形成正式测试报告时必须固定使用哪一种模型，不能把两种计算值混在同一数据表中。

## 4. 怎样取得可称为真实测量值的角度

### 第一步：确认26.88°覆盖范围和实际方向

现已确认26.88°是设备垂直视场角。接下来需要确认它覆盖线阵Sensor的完整 `Width Max`，还是当前 `Width+Offset X`裁剪后的有效范围；并记录是否经过Binning、缩放和数字畸变校正。由于本项目在检测前旋转图像90°，还应以一个已知上下方向的目标确认处理后 `panoY` 的正负关系。

### 第二步：标定线阵空间轴的角度映射

线阵输出帧的另一维来自运动和逐行曝光，不能把一幅4096×4096合成帧直接当作普通面阵相机的单次曝光图，用静止棋盘格套用二维面阵标定。应分别在RGB、BW相机的实际镜头、焦距和调焦状态下，标定Sensor空间线轴：

```text
βrel = g(xline; cs, fs, distortion)
```

其中`cs`是线阵空间轴主点、`fs`是像素焦距，`distortion`为沿该轴的镜头畸变模型；按当前旋转/镜像关系也可等价写成：

```text
βrel = g'(panoY; cy, fy, distortion)
```

推荐用经纬仪/转台给出已知仰角的远距离点光源、准直目标或高对比度标志，使目标依次落在线阵上、中、下多个位置，直接拟合“空间像素—真实相对高度角”曲线。若使用棋盘格或Charuco板，必须采用适合线阵相机的受控平移/转动采集方法，同时保存行触发和编码器位置；不能使用面阵相机的静态拍摄流程。

识别到目标后，先把检测框中心换算到对应的线阵空间坐标并应用该标定曲线。没有标定时，只能使用第3节的理想模型，不能以名义图像中心替代实测主点并声称是真值。

### 第三步：标定双通道偏移

用远距离共同目标同时采集RGB/BW图像，在至少上、中、下三个高度位置统计配准残差。为每个通道保存纵向修正量或线阵射线映射，并记录标定版本；只有在扫描行和编码器角度同步后，才适合估计包含扫描方向的二维全景配准。

### 第四步：取得光轴外参和平台姿态

如果设备滚转可忽略，可用已知水平线或经纬仪测得光轴俯仰 `βaxis`，近似计算：

```text
βabs ≈ βaxis + βrel
```

若设备有滚转、俯仰变化，应把去畸变后的相机视线向量乘以相机到世界坐标的旋转矩阵 `Rworld←camera`。设变换后的单位向量为 `[rE,rN,rU]`：

```text
方位角 θabs = atan2(rE,rN)
高度角 βabs = atan2(rU, sqrt(rE²+rN²))
```

方位零位还应与转台编码器和正北方向标定；界面北向显示偏置不得回写原始测量角。

对于线阵扫描方向的真实方位，优先保存每条采集行对应的编码器角度。如果暂时只能得到一帧的起止编码器角，可按行序号插值得到初值：

```text
θline(j) = unwrap(θstart) + j/(Height-1) × [unwrap(θend)-unwrap(θstart)]
```

其中还要补偿曝光时刻、触发延迟、网络接收延迟和扫描方向。只有在行频与角速度稳定、每圈采样均匀时，才能用 `panoX/65536×360°`作为等价近似。

### 第五步：用已知角度目标做独立验证

建议用经纬仪、全站仪或已知坐标远距离地标，在视场上、中、下及左右位置取得不少于9～15个控制点。至少记录：

| 时间 | 通道 | 控制点 | `panoX` | `panoY` | 预测方位 | 真值方位 | 预测高度角 | 真值高度角 | 误差 | 标定版本 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |

正式材料应给出平均误差、最大绝对误差和P95误差，并另外保留未参与标定的验证点。

## 5. 目标框的角尺寸

若需要知道检测目标在画面中占据多少角度，应分别换算目标框边缘：

```text
βtop    = elevation(panoBoxY1)
βbottom = elevation(panoBoxY2)
目标垂直角尺寸 = |βtop-βbottom|
```

全景已按360°等角横向展开时，可先估算：

```text
目标水平角尺寸 ≈ circularPixelSpan(panoBoxX1,panoBoxX2) × 360°/65536
```

该角尺寸只能结合距离进一步换算物理尺寸。例如小角度条件下，目标高度近似为“斜距×垂直角尺寸（弧度）”；没有距离时不能得到米制尺寸。

## 6. 使用随附计算工具

单个目标按针孔模型计算：

```bash
python3 目标视线角计算工具.py --pano-y 2856 --pano-x 29437
```

复现当前软件线性模型：

```bash
python3 目标视线角计算工具.py --pano-y 2856 --model linear
```

已有标定主点、焦距和光轴俯仰时：

```bash
python3 目标视线角计算工具.py \
  --pano-y 2856 --cy 2051.2 --fy-px 8562.4 \
  --y-offset-px -3.1 --axis-pitch-deg 1.25
```

批量处理候选JSONL：

```bash
python3 目标视线角计算工具.py \
  --input-jsonl /路径/direct_yolo_manifest.jsonl \
  --output-csv /路径/目标视线角结果.csv
```

工具输出中的 `calibrationLevel=fov_only_model_estimate` 表示只有FOV模型估算，不能标成真实绝对测角；只有在输入标定 `cy、fy` 并进一步完成畸变和姿态处理后，才可升级材料中的测量表述。

## 7. 建议写入正式日志的字段

```text
targetId, sourceFrameKey, stream, timestamp,
panoX, panoY, panoBoxX1, panoBoxY1, panoBoxX2, panoBoxY2,
rawAzimuthDeg, relativeElevationDeg, absoluteElevationDeg,
verticalAngularSizeDeg, calibrationVersion, calibrationLevel,
fovDeg, principalPoint, focalLengthPx, distortionVersion,
axisPitchDeg, rollDeg, azimuthZeroDeg
```

必须同时保存原始 `panoX/panoY` 和标定版本，便于标定更新后对历史检测重新计算，而不是只保存一个无法追溯的角度结果。
