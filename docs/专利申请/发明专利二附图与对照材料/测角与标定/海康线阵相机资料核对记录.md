## 2. 线阵坐标与当前软件坐标的结论

设海康线阵输出帧的原始坐标为 `(xline,yline)`：

- `xline`沿Sensor线方向，范围由`Width/Offset X`决定，本设备安装后对应26.88°垂直视场；
- `yline`是随转台运动累计的行号，范围由`Height`决定，对应扫描时间/方位。

当前软件先逆时针旋转90°，再水平镜像。在不缩放时：

```text
xprocessed = Height - 1 - yline
yprocessed = Width  - 1 - xline
```

因此：

```text
panoY ← Sensor的有效Width轴 ← 垂直视场角26.88°
panoX ← 累计扫描行/转台运动 ← 编码器方位
```

这说明当前使用`panoY`换算目标相对高度角的方向是合理的，但还需用已知高、低控制点确认正负；使用`panoX/65536×360°`换算方位只在扫描角速度和行频均匀时成立，正式测角宜改为逐行编码器角度或分段起止角插值。

软件证据包括：

- `tools/dmx_direct_yolo_worker.py`的`rotate_for_panorama()`先执行`ROTATE_90_COUNTERCLOCKWISE`，再执行水平翻转；
- `dmx_config.json`配置`fullWidth=65536`、`fullHeight=4096`和`verticalFovDeg=26.88`；
- `mainwindow.cpp`当前仅在测试构建中按`panoY`线性换算`elevationAngleDeg`，尚未接入线阵内参、畸变和姿态标定。

- Sensor的具体芯片料号；两路有效像元数、线数和像元尺寸已由型号规格书确认；
- 两个镜头的型号、焦距、工作距离和畸变；

- 当前`Width、Height、Offset X、Binning、Reverse X、Reverse Scan Direction`值；
- 当前行频、触发方式、编码器参数和逐行时间/角度；
- 线阵空间轴主点/像素焦距`c_s、f_s`（处理后等价为`c_y、f_y`）及畸变参数；

原因不是资料读取遗漏，而是该文件本身属于系列通用操作手册。手册明确要求具体技术参数查看相应型号的技术规格书。

## 6. 线阵标定注意事项

一幅线阵输出帧虽然是二维图像，但其中`Height`方向由连续行曝光和机械扫描合成，不是面阵传感器的第二条空间像素轴。因此：

1. 垂直高度角应标定线阵`Width`方向的一维射线模型或“像素—仰角”查找表；
2. 方位角应标定“累计行号—曝光时刻—编码器角度”的对应关系；
3. 普通面阵相机的静态棋盘格内参流程不能原样用于这类合成帧；
4. RGB/BW两通道必须分别标定，再用共同远距离控制点做射线层配准。
